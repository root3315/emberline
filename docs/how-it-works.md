# Как это устроено

Разбор проекта целиком: откуда берутся данные, что с ними происходит по дороге
и какой файл за что отвечает. Читать можно подряд — порядок повторяет путь
одной засечки от спутника до пикселя на экране.

> **In English:** this is the long-form walkthrough and it is in Russian.
> Everything needed to build and run the project — including the full
> rebuild order for the world data and the Python model — is in
> [README.md](../README.md), in English.

---

## 1. Задача, и почему она не тривиальная

NASA даёт два семейства приборов, которые видят одно и то же:

- **MODIS** на спутниках Terra (с 2000) и Aqua (с 2002). Пиксель — 1 км.
- **VIIRS** на Suomi-NPP (с 2012), NOAA-20 (2018) и NOAA-21 (2024). Пиксель —
  375 м.

Если просто сложить их засечки и построить график по годам, получится, что в
2012 году планета вспыхнула. Это неправда: просто на орбиту вышел прибор в
семь раз более зоркий. Вот эти два числа — из нашего собственного индекса:

| год | засечек MODIS | засечек VIIRS |
|---|---|---|
| 2011 | 4.4 млн | 0 |
| 2012 | 4.8 млн | 19.5 млн |

Убрать эту ступеньку, не подделав данные, — и есть задача проекта. Всё
остальное строится вокруг неё.

**Как она решается.** Берутся дни, когда оба семейства смотрели на одну и ту
же землю, и считается отношение: во сколько раз больше видит VIIRS. Медиана
этих отношений — коэффициент, на который умножается весь ряд: сравнимая
серия строится из ячейко-дней MODIS на всём протяжении, потому что MODIS —
единственный прибор, который не менялся. Он
**меряется для каждой области отдельно**, потому что зависит от того, насколько
раздроблены пожары: стерня на поле дробится не так, как верховой пожар в тайге.
Для Пенджаба, где горит стерня, вышло 7.07 (межквартильный размах 3.88–13.52 по 3018 парным дням); для якутской тайги, где пожар и так велик для километрового пикселя, — 1.88. Между ними Сьерра 2.56 и Серрадо 2.13. Единого числа для планеты мы не считаем: оно было бы средним по четырём разным ответам.

Код: `src/core/harmonize.ts`, функции `dailySensitivityRatios`,
`summarizeSensitivity`, `applySensitivity`.

## 2. Путь данных

```
FIRMS API  →  кэш на диске  →  свёртка в пирамиду  →  файлы сайта  →  браузер
  (сеть)      11 ГБ .csv.gz      скрипты scripts/       public/data/    src/
```

### Шаг 1. Выгрузка — `scripts/build-archive.ts`

Единственный скрипт, который ходит в сеть. Качает окнами по 5 суток (больше
API не отдаёт) по каждому продукту и складывает сырые `.csv.gz` в кэш.

Что там нетривиального:

- **Квота.** 5000 транзакций на ключ за 10 минут, и цена запроса считается **по
  площади**, а не по числу дней: глобальное пятисуточное окно стоит ~180
  транзакций, а не 10. Скрипт меряет цену на ходу и распределяет запросы по
  девяти ключам скользящим окном.
- **Полоса.** Замерено: потолок скорости принадлежит соединению, а не ключу.
  Лишние ключи покупают квоту, но не скорость.
- **Кэш по окнам.** Прогон можно прерывать: докачается с места обрыва.

### Шаг 2. Свёртка — `scripts/build-world-*.ts`

Сеть больше не нужна: эти скрипты читают кэш и пишут файлы сайта. Все они
разбирают CSV **побайтно** — на 631 млн строк обычный `split(',')` создал бы
десять миллиардов временных строк и часы сборки мусора. Вместо этого буфер
обходится байтами, поля находятся по запятым, числа читаются прямо из байтов.
Ничего не превращается в строку, скорость — около 15 МБ/с.

| скрипт | что делает | результат |
|---|---|---|
| `build-world-l0.ts` | сетка 1°, помесячно | 27 файлов, 33 МБ + индекс |
| `build-world-l1.ts` | сетка 0.25°, помесячно | 108 файлов, 196 МБ |
| `build-world-l2.ts` | сетка 0.05°, за год, тайлами 20° | 2971 файл, 102 МБ |
| `build-world-l3.ts` | сетка 0.01°, за год, тайлами 10° | 8094 файла, 463 МБ |
| `build-world-days.ts` | посуточно, 0.25°, тайлами 10° | 2150 файлов, 233 МБ |
| `build-world-now.ts` | последняя неделя: сетка + точки | 1.5 МБ |
| `build-world-ramp.ts` | потолки шкалы цвета | 1 файл |
| `build-emissions.ts` | оценка CO₂ по годам | 1 файл |
| `build-climate.ts` | температура NASA GISTEMP | 1 файл |

### Шаг 3. Браузер — `src/`

Страница не «загружает архив». Она берёт ровно тот уровень пирамиды, который
нужен текущему кадру, и ровно те тайлы, которые в него попали. Планета — это
один мегабайт; район — тридцать килобайт.

## 3. Пирамида: зачем четыре уровня

Одна и та же сетка не годится и для планеты, и для района.

| уровень | ячейка | на экране | когда включается |
|---|---|---|---|
| L0 | 1° (111 км) | планета целиком | зум < 5 |
| L1 | 0.25° (25 км) | страна | зум 5–7.5 |
| L2 | 0.05° (5 км) | область | зум 7.5–9.5 |
| L3 | 0.01° (1 км) | район | зум ≥ 9.5 |
| точки | — | отдельные засечки | зум ≥ 9.5, режим «сейчас» |

**Ниже километра сетки нет и не будет.** Пиксель MODIS в надире ровно
километр, а к краю полосы обзора расплывается до пяти. Сетка мельче
приписывала бы прибору точность, которой у него нет. Что переживает
дальнейший зум — сами засечки точками, и они есть для живой недели.

Выбор уровня: `src/core/world.ts`, `levelForZoom` и `levelForBounds`. Второй
нужен потому, что при выборе места камера ещё не двинулась, а уровень уже надо
знать — иначе первый кадр страны рисуется в разрешении планеты.

## 4. Файлы `src/`, по одному

### Ядро — `src/core/`

| файл | ответственность |
|---|---|
| `harmonize.ts` | сведение MODIS и VIIRS: измерение коэффициента и его применение |
| `world.ts` | загрузка всех глобальных уровней, тайлов, посуточного куба и точек |
| `grid.ts` | календарная арифметика: день года, високосные годы |
| `stats.ts` | климатология, перцентили, сезоны, «горячие» дни |
| `cube.ts` | формат региональных архивов (четыре встроенных района) |
| `aoi.ts` | описание этих четырёх районов |
| `geocode.ts` | поиск места по названию (Nominatim) |
| `emissions.ts` | метод оценки CO₂ и загрузка готового ряда |
| `types.ts` | общие типы |

### Интерфейс — `src/ui/`

| файл | что рисует |
|---|---|
| `ribbon.ts` | лента-календарь: строка — год, квадратик — день |
| `map.ts` | карта Leaflet и свой canvas-слой поверх неё |
| `cycle.ts` | график выбранного года против «обычного» |
| `contrib.ts` | засечки по приборам, год за годом |
| `world-panel.ts` | сезон планеты и «Год за годом» с линией температуры |
| `picker.ts` | выбор района с поиском по всей Земле |
| `paint.ts` | цветовая шкала, вспомогательная отрисовка |
| `burn.ts` | переход между тёмной и светлой темой |

### Сборка — `src/main.ts`

Один файл, который всё соединяет: состояние, маршрутизация по адресу,
переключение режимов. Ключевые функции:

- `goTo(value)` — единственное место, где решается, что открыть: встроенный
  регион, планета или найденное место. Раньше этот выбор был скопирован в трёх
  местах и в каждом сломан по-своему.
- `renderMapWorld()` — выбирает уровень, догружает тайлы, рисует карту.
- `drawScopeRibbon()` — рисует ленту той области, которая открыта.
- `wantedWorldLevel()` — какой уровень пирамиды заслуживает текущий кадр.

## 5. Почему карта — свой canvas, а не Leaflet-объекты

На 5-километровой сетке большая область — это десятки тысяч квадратов. Столько
объектов Leaflet превращают вкладку в слайд-шоу. Поэтому сетка рисуется одним
холстом поверх карты, а во время жеста зума не перерисовывается, а масштабируется
— как это делают все рендереры карт.

Здесь была тонкая ошибка, которую стоит помнить: холст надо пересчитывать
**относительно того кадра, для которого он нарисован**, а не относительно
текущего. Иначе масштаб выходит 1, и точки стоят на месте, пока карта под ними
едет.

## 6. Цвет: почему шкала глобальная

Ячейка красится относительно потолка. Если потолок брать по тому, что попало в
кадр, — на планете читается верно, а на выбранном городе врёт: сто ячеек со
значениями от 1 до 48 превращают 48 в «максимум шкалы», и обычные палы вокруг
города красятся как Серрадо в августе.

Поэтому `ramp.json` хранит потолок **по всей Земле** для каждого уровня и
каждого года — 99-й процентиль. Тёмная ячейка значит «верхняя сотая доля
горящей земли в этом году», где бы ни стояла камера.

Потолок по годам, а не на весь ряд: иначе всё до 2012-го обесцветилось бы из-за
прихода VIIRS.

## 7. Оценка CO₂: что честно, а что нет

Считать выбросы по числу засечек нельзя — засечка означает «пиксель был
горячим», а не «сгорело столько-то». Принятый метод идёт от энергии:

```
мощность излучения → энергия → сожжённая биомасса → CO₂
```

**И вот где нужна честность.** Мощность — мгновенная величина, энергия — её
интеграл по времени, а спутник видит пожар 2–4 раза в сутки. Превратить
несколько снимков в интеграл можно только предположив, сколько времени
«представляет» каждый — и это предположение из наших данных не выводится.

Поэтому оно калибруется: коэффициент подобран так, чтобы итог по эпохе MODIS
сошёлся с опубликованным GFED (7.3 Гт CO₂ в год). Значит, **мы не измеряем
выбросы независимо** — мы раскладываем известный мировой итог по нашим годам.
Это полезно, но в подписи так и написано.

Считается **только по MODIS**, потому что общий ряд мощности имеет ту же
ступеньку. И это видно в цифрах:

| год | мощность MODIS | мощность VIIRS |
|---|---|---|
| 2003 | 2.28·10⁸ | 0 |
| 2012 | 2.19·10⁸ | 2.04·10⁸ |
| 2024 | 2.00·10⁸ | 6.49·10⁸ |

MODIS почти не меняется, общая сумма выросла втрое. Весь «рост пожаров» в
общем ряду — это новые спутники.

Код: `src/core/emissions.ts` (метод и константы), `scripts/build-emissions.ts`
(считает один раз при сборке).

## 8. Как запустить

```bash
npm install
npm run dev          # сайт на localhost:5178
npm run typecheck    # проверка типов: и src/, и scripts/
npm run build        # сборка в dist/
```

Данные в `public/data/world/` не лежат в гите — гигабайт бинарников. Если их
нет, сайт работает: карта упрётся в 25 км, календарь останется у четырёх
встроенных регионов. Восстановить из кэша:

```bash
npx tsx scripts/build-world-l0.ts <кэш>
npx tsx scripts/build-world-l1.ts <кэш>
npx tsx scripts/build-world-l2.ts <кэш>
npx tsx scripts/build-world-l3.ts <кэш>
npx tsx scripts/build-world-days.ts <кэш>
FIRMS_MAP_KEYS=... npx tsx scripts/build-world-now.ts 7
npx tsx scripts/build-world-ramp.ts
npx tsx scripts/build-emissions.ts
npx tsx scripts/build-climate.ts
```

Ключи FIRMS — в `.env`, в гит не попадают. Нужны только для `build-archive.ts`
и `build-world-now.ts`; остальные скрипты в сеть не ходят.

## 9. Ошибки, на которых мы уже обожглись

Стоит прочитать до того, как трогать свёртку.

**Колонка `type`.** Научные продукты (SP) несут 15 колонок, near-real-time —
14, без `type`. Код требовал 14 запятых и **молча выбрасывал все NRT-строки**.
На глобальном архиве это июль, август и сентябрь 2026 — три свежих месяца,
читавшихся как ноль пожаров на всей планете. Ничего не падало. Вернулось 65 млн
засечек.

**Цена запроса по площади.** Считали по числу суток — ошиблись в 12 раз и
сожгли квоту девяти ключей за десять минут.

**Обрезка карты по рамке.** Когда карту обрезали по выбранной рамке, потолок
цветовой шкалы стал считаться только по видимым ячейкам — и город «загорелся».
Одна правка сломала другое место; отсюда глобальный `ramp.json`.

**Лента, нарисованная в скрытый блок.** Компонент берёт размеры из своего
контейнера. Если рисовать, пока блок скрыт, слой для наведения остаётся
высотой 150 px: картинка верная, а подсказка не работает.

## 10. Модель и прогноз

Архив отвечает на вопрос «когда здесь горит». Вторая половина проекта
отвечает на «где загорится на следующей неделе», и построена тем же
доводом, только приложенным к другому вопросу.

**Что именно спрашивают.** Цель — «увидит ли километровый сенсор MODIS
огонь в этой ячейке за N дней». Намеренно не сведённый ряд: цель, которая
растёт вместе с составом спутниковой группировки, научила бы модель
спутникам, а не пожарам. MODIS летает с тем же сенсором с 2002 года — и с
2003-го парой, — поэтому вопрос звучит одинаково во все годы.

**На чём учат.** Градиентный бустинг (`HistGradientBoostingClassifier`)
читает 25 признаков про каждую ячейку 0.25° планеты: как часто здесь
горит в это время года, как давно горело, что делается у соседей,
насколько год отошёл от своей нормы, где Эль-Ниньо — и прогноз погоды на
неделю вперёд, то есть ту половину, которую архив пожаров дать не может
ни при каком разрешении.

**Разбиение — по эпохам, никогда случайно.** Учится на 2003–2013,
настраивается на 2014–2017, оценивается на 2018–2021. Соседние дни одной
ячейки — почти один и тот же пример, поэтому случайное разбиение даёт
красивые числа и никакого умения. Тест кончается 2021-м, потому что там
кончается погодный архив.

**Выборка и обратная поправка.** При базовой доле около 5% модель,
накормленная сырыми данными, учится отвечать «не загорится». Поэтому в
обучении три отрицательных примера на один положительный, а выход
возвращается к истинной доле аналитическим сдвигом логита. Тестовая
выборка берётся при естественной доле и не трогается.

**Семь моделей, а не одна.** По одной на горизонт от суток до недели: про
вторник надо спрашивать модель, которую спрашивали про вторник. Короткие
окна удержаны не выше длинных — «к среде» содержит «ко вторнику».

**Чем меряют.** Средняя точность 0.558 против 0.533 у климатологии и
0.387 у «горело на прошлой неделе», при базовой доле 0.05. Погода даёт
примерно +0.012.

**И проверка вперёд.** Прогноз считается до начала своей недели, а потом
сверяется с тем, что сообщила NASA. Это единственное число на сайте,
которое нельзя было подогнать, потому что ответа не существовало в момент
вопроса. `verify_forecast.py` его пишет, кладёт рядом бесплатную базу
(«горело на прошлой неделе»), отдельно считает ту часть карты, где этой
базе сказать нечего, и отказывается показывать калибровку, пока неделя не
закрылась. Каждая проверенная неделя остаётся в `verify-history.json`
навсегда — в том числе неудачная.

**Что попробовали и выбросили.** Подогнанная калибровочная кривая
(изотоника и Платт — ни одна не прошла порог), население (+0.00013
средней точности, 12-е и 13-е места из 27) и больше деревьев (валидация
достигает максимума на 200 и дальше идёт назад). Все три — на странице
«о проекте», а не в ящике.

**Где что лежит.** `scripts/train_fire_model.py` строит матрицу
признаков, `fit_fire_model.py` и `fit_fire_model_v2.py` учат,
`build_forecast.py` применяет модель к концу записи,
`build_horizons.py` делает то же по горизонтам, `build_reasons.py`
считает по три причины на ячейку, `verify_forecast.py` сверяет. Порядок
запуска и что нужно из ключей — в [README.md](../README.md).
